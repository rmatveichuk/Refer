## 1. Резюме проверки (Executive Summary)

В ходе аудита подтверждено:
1. **Сохранность данных библиотеки:** Действие пользователя «Скрыть из библиотеки» (кнопка `Del`, панель инструментов, контекстное меню таблицы и галереи, просмотрщик изображений) **полностью исключает** удаление записей из таблиц SQLite (`assets`, `asset_tags`, `tags`, `projects`, `sources`), не сбрасывает векторы в индексе FAISS и не затрагивает физические файлы на локальных/сетевых дисках.
2. **Изоляция и семантическая фильтрация:** Скрытые ассеты исключаются из выдачи во всех режимах поиска (семантический поиск SigLIP 2, фильтрация по тексту/метаданным, тегам, избранному, кураторскому ТОПу и разделам каталога). Сброс поисковой строки или фильтров не приводит к появлению скрытых изображений.
3. **Бесшовное восстановление:** Восстановление изображений через экран «Скрытые» возвращает ассеты с сохранением их оригинальных тегов, флага избранного и векторных представлений **без повторного сканирования, загрузки по сети или нейросетевого инференса**. Если каталог ассета отключён в настройках, ассет остаётся скрытым из поиска в соответствии со статусом каталога.
4. **Безопасная диагностика файлов:** Механизм проверки доступности файлов (`database/availability.py`) является строго неизменяющей (`read-only`) операцией. Он надежно отличает физически отсутствующий файл от временно отключённого диска/сетевой шары (`source_unavailable`) и ошибок прав доступа (`PermissionError`). **Автоматическое удаление при недоступности накопителей категорически исключено.**

## 2. Детальная верификация контрольных пунктов задания

### Пункт 1. Все пути пользовательского удаления вызывают скрытие, ветки без главного окна безопасны
* **Галерея (`ui/widgets/gallery_view.py`):**  
  Метод `_delete_assets(assets)` проверяет наличие родительского окна:
  ```python
  if not self.db:
      return
  if self.parent_window and hasattr(self.parent_window, "_delete_assets_batch"):
      self.parent_window._delete_assets_batch(assets)
  ```
  Если галерея встроена автономно без `parent_window`, вызов безопасно прерывается. Физическое удаление файлов и использование необъявленных переменных отсутствуют.
* **Полноразмерный просмотрщик (`ui/widgets/image_viewer.py`):**  
  Метод `_delete_current_asset()` содержит строгую проверку граничных условий:
  ```python
  if self.current_index < 0 or not self.parent_window:
      return
  asset = self.assets[self.current_index]
  self.parent_window._delete_assets_batch([asset])
  self.assets.pop(self.current_index)
  ```
  Делегирование выполняется исключительно в `parent_window._delete_assets_batch`. Никаких локальных `os.remove()` или прямых SQL-запросов на удаление нет.
* **Главное окно (`ui/main_window.py`):**  
  Метод `_delete_assets_batch(assets)`:
  - Формирует список уникальных ID.
  - Пакетами по 500 штук запрашивает актуальные записи из базы (`SELECT * FROM assets WHERE id IN (...)`).
  - Запрашивает явное подтверждение пользователя через `QMessageBox.question` с текстом: *«Скрыть N изображений из библиотеки? Вернуть их можно через «Скрытые». Файлы, теги и избранное сохраняются.»*
  - Вызывает `self.visibility.hide(rows)`.
  - Обновляет только представление галереи `self._load_assets_for_gallery()`. В базе данных не выполняется ни одного `DELETE` или деструктивного `UPDATE`.

### Пункт 2. Исключение скрытых изображений из всех срезов поиска
* **Архитектура фильтрации (`database/search_repository.py`):**  
  Все запросы формирования выборки ассетов проходят через единый метод `SearchRepository.candidates(filters)`:
  ```python
  hidden = self.visibility.entries()
  def allowed(row):
      if self.visibility.is_hidden(row, hidden):
          return False
      ...
  ```
* **Проверенные срезы и режимы:**
  - **Семантический векторный поиск:** После извлечения ближайших соседей из индекса FAISS и сопоставления по ID, функция `allowed()` отсекает любые скрытые ассеты до возврата в UI.
  - **Текстовый поиск по метаданным:** Поиск по авторам, проектам и описаниям выполняется только по кандидатам, прошедшим `allowed()`.
  - **Теги и исключающие теги:** Фильтры `tags`, `exclude_tags`, режим совпадения `all`/`any` накладываются на уровне SQL/кандидатов, скрытые ассеты отсекаются.
  - **Избранное (`favorites=True`):** Скрытые ассеты с `is_favorite = 1` не попадают в список кандидатов.
  - **Кураторский ТОП (`top_only=True`):** Фильтр по тегу `топ`/`top` исключает скрытые ассеты.
  - **Разделы каталога («Референсы», «3D-модели», «Растения»):** Исключение скрытых выполняется до разделения по секциям.
* **Сброс фильтров:** Вызовы `_clear_all()` и `reset_filters()` сбрасывают текстовые запросы и комбобоксы, но последующий вызов `candidates()` повторно считывает `self.visibility.entries()` и сохраняет скрытие.

### Пункт 3. Восстановление без повторного импорта/инференса и изоляция отключённых каталогов
* **Механизм восстановления:**
  В диалоге `HiddenAssetsDialog` и методе `MainWindow._restore_hidden_assets(ids)` вызывается `self.visibility.restore(ids)`. При этом из JSON-файла `hidden_assets.json` просто удаляются соответствующие ключи.
* **Сохранность метаданных и векторов:**
  Так как записи в таблицах `assets`, `asset_tags`, `tags` и FAISS-индексе никогда не удалялись, восстановленный ассет мгновенно становится доступен со своими старыми тегами, автором, описанием и вектором без повторной векторизации SigLIP 2 и без обращения к диску.
* **Взаимодействие с отключёнными каталогами (`disabled_sources`):**
  В `database/search_repository.py` (строки 109–112):
  ```python
  normalized = normalized_path(path)
  if any(normalized == normalized_path(excluded) or normalized.startswith(normalized_path(excluded) + "/")
         for excluded in filters.excluded_sources):
      return False
  ```
  Если каталог был отключён пользователем в `CatalogDialog`, его путь находится в `filters.excluded_sources`. Восстановление отдельного ассета удаляет его из списка скрытых, однако условие `excluded_sources` продолжает отсекать его. Ассет появится в галерее только тогда, когда пользователь снова включит каталог целиком.

### Пункт 4. Поведение при повторном сканировании папок
* **Логика дедупликации (`scrapers/local_folder.py`):**  
  Перед обработкой файлов сканер опрашивает базу:
  ```python
  cur.execute("SELECT local_path FROM assets WHERE local_path IS NOT NULL AND local_path != ''")
  existing_paths = {normalized_local_path(row['local_path']) for row in cur.fetchall()}
  ```
  При обходе файловой системы:
  ```python
  path_key = normalized_local_path(file_path)
  if path_key in existing_paths:
      continue # Уже есть в БД
  ```
* **Результат:** Так как скрытые ассеты остаются в таблице `assets`, их `local_path` присутствует в множестве `existing_paths`. Сканер пропускает такие файлы: новые записи не создаются, дубликаты не размножаются, статус скрытия в `hidden_assets.json` не сбрасывается.

### Пункт 5. Отказоустойчивость и атомарность `VisibilityStore`
* **Атомарная запись через временный файл (`database/visibility_store.py`):**
  Запись производится во временный файл в том же каталоге (`dir=self.path.parent`), вызывается `file.flush()` и принудительный сброс на диск `os.fsync(file.fileno())`, после чего выполняется атомарная замена `os.replace(temp_path, self.path)`.
* **Сценарий сбоя записи (`OSError`):**
  В блоке `finally` гарантированно удаляется временный файл (`temp_path.unlink()`), если замена не состоялась. Исходный файл `hidden_assets.json` не повреждается. Метод выбрасывает `RuntimeError("Не удалось сохранить скрытые изображения. Библиотека не изменена.")`.
  Вызывающий метод `MainWindow._delete_assets_batch` перехватывает исключение, отображает `QMessageBox.critical` и возвращает `False`, не рапортуя об успехе и не обновляя галерею.
* **Сценарий повреждённого файла состояния:**
  Если JSON повреждён (битый синтаксис, обрыв питания) или нарушена структура (отсутствует `"version": 1`, не-числовые ID или хеш не равен 64 символам), метод `entries()` выбрасывает `RuntimeError`. Он **не возвращает пустой словарь `{}` молча**, что предотвращает случайное снятие скрытия со всех ранее скрытых ассетов.

### Пункт 6. Привязка к идентичности записи (`asset_identity`)
* **Алгоритм хеширования идентичности:**
  ```python
  def asset_identity(asset):
      origin = row.get("original_url") or normalized_path(row.get("local_path") or row.get("thumbnail_path") or "")
      payload = json.dumps([origin, row.get("phash") or ""], ensure_ascii=False)
      return hashlib.sha256(payload.encode("utf-8")).hexdigest()
  ```
* **Защита от коллизий при пересоздании/замене базы:**
  В `VisibilityStore.is_hidden(row)` проверяется совпадение сохранённого SHA-256 хеша:
  ```python
  expected = entries.get(str(row["id"]))
  return expected is not None and expected == asset_identity(row)
  ```
  Если база данных была заменена, импортирована заново или ID были переиспользованы для совершенно другого изображения, вычисленный `asset_identity(row)` не совпадёт со значением `expected`. Другое изображение с тем же ID **не будет скрыто**.

### Пункт 7. Диагностика доступности файлов (`database/availability.py`)
* **Strict Read-Only:** Функция `inspect_files(db, cancellation, progress)` выполняет единственный SQL-запрос `SELECT a.id, a.local_path, a.thumbnail_path, a.image_type, s.domain ...`. Никаких операций модификации БД SQLite или файлов индекса FAISS не производится.
* **Дифференциация причин недоступности:**
  - **`source_unavailable`:** Корневой каталог или диск недоступен (`os.stat(root)` возвращает ошибку или диск отключён). Фиксируется статус `source_unavailable` с сообщением: *«Источник недоступен; данные сохранены»*.
  - **`file_missing`:** Корневой каталог доступен, но конкретный файл отсутствует внутри него (`stat_state == 'missing'`).
  - **`file_unavailable`:** Ошибка доступа к файлу (`PermissionError`), некорректный путь или путь указывает на каталог вместо обычного файла (`stat.S_ISREG`).
  - **`preview_missing` / `preview_unavailable`:** Для веб-ассетов фиксируется состояние локального превью при сохранении данных об источнике.
* **Диалог результатов (`ui/availability_dialog.py`):**
  Интерфейс содержит только информационную таблицу и единственную кнопку «Закрыть» (`QDialogButtonBox.StandardButton.Close`). Любые кнопки массового автоматического удаления отсутствуют.

### Пункт 8. Документированные границы и архитектурные ограничения
1. **Бюджеты памяти миниатюр vs Полноразмерный просмотрщик / Модели:**
   Лимиты оперативной памяти и LRU-кеширование миниатюр (класс `QPixmapCache` и `GalleryModel`) распространяются только на сетку превью (разрешение до 1024px WebP). Окно `ImageViewerWindow` и модель инференса `AiEngine` работают напрямую с оригинальными локальными файлами высокого разрешения, минуя кеш галереи.
2. **Устаревшие маркеры удаления (`deleted_assets`):**
   Таблица `deleted_assets` использовалась в ранних версиях Refer для записи URL удалённых ассетов после их физического удаления из `assets`. Существующие строки в `deleted_assets` не мигрируют автоматически в `hidden_assets.json` (так как сами записи из таблицы `assets` уже были удалены в старых версиях).
3. **Ранее существовавшие дубликаты:**
   Новый механизм предотвращает появление дубликатов при повторном сканировании, однако дубликаты, уже присутствовавшие в базе до внедрения `VisibilityStore`, автоматически не дедуплицируются.

### Замечание 1 (Low / Code Smell): Неполная инициализация объекта `Asset` при удалении из таблицы
* **Файл:** [ui/main_window.py](file:///c:/Users/RMatv/OneDrive/Рабочий%20стол/Dev/Refer/ui/main_window.py#L588-L596)
* **Контекст:** В методе `_delete_selected_asset()` создаётся временный объект `Asset` для передачи в `_delete_assets_batch`:
  ```python
  asset = Asset(
      id=row['id'], original_url=row['original_url'],
      thumbnail_path=row['thumbnail_path'], phash=row['phash'],
      project_id=row.get('project_id'),
      image_type=row['image_type'] or 'Photography'
  )
  self._delete_assets_batch([asset])
  ```
  В конструктор `Asset` не передаётся аргумент `local_path=row.get('local_path')`.
* **Почему сейчас работает:** Метод `_delete_assets_batch([asset])` извлекает только `asset.id` и повторно запрашивает полную строку `SELECT * FROM assets WHERE id IN (...)` из SQLite, где `local_path` уже присутствует.
* **Рекомендация для Codex:** Передавать `local_path=row.get('local_path')` явно для сохранения чистоты контракта модели `Asset`.

### Замечание 2 (Environment / High Risk for Production): Несовместимость версий `numpy` и `faiss-cpu` в системном окружении
* **Проблема:** В глобальном окружении Python 3.12 установлен пакет `numpy==2.5.2`, в то время как установленный бинарный пакет `faiss-cpu==1.8.0` скомпилирован под C-API NumPy 1.x.
* **Проявление:** При прямом импорте `import faiss` возникает критическая ошибка:
  ```text
  ImportError: numpy.core.multiarray failed to import
  ```
* **Рекомендация:** В [requirements.txt](file:///c:/Users/RMatv/OneDrive/Рабочий%20стол/Dev/Refer/requirements.txt) уже зафиксирована версия `numpy==1.26.4`. При развертывании и сборке приложения необходимо принудительно устанавливать `numpy<2` (`pip install "numpy<2"`), чтобы избежать падения приложения при инициализации векторного поиска.
