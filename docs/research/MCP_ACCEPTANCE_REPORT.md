## 2. Устранение критических замечаний P1

### 2.1. Устранение зависания клиента при обрыве связи (Lock Reentrancy & Deadlock)
* **Проблема:** В `ai/shared_service.py` класс `SharedAiClient` использовал нерекурсивный `threading.Lock()`. При возникновении сетевой ошибки (например, `ConnectionResetError` или таймаут сокета) блок `except` в методе `_request` вызывал `self.close()`, который повторно пытался захватить тот же `self._lock`. Возникал мгновенный взаимный дедлок: вызывающий поток зависал навсегда, а последующие вызовы блокировались. Аналогично путь без сокета вызывал `_connect_or_spawn()` под тем же захваченным замком.
* **Решение:**
  - В [`ai/shared_service.py`](file:///c:/Users/RMatv/OneDrive/Рабочий%20стол/Dev/Refer/ai/shared_service.py) `self._lock` заменён на рекурсивный `threading.RLock()`.
  - При ошибке сокета метод `close()` очищает сокет и файловые дескрипторы без дедлока, а `_request` гарантированно выбрасывает `RuntimeError` вызывающему потоку.
  - При следующем обращении клиент видит `_sock is None`, выполняет чистое переподключение (`_try_connect_existing` или `_connect_or_spawn`) и возвращает результат без необходимости перезапуска приложения.
* **Тесты:**
  - В `tests/test_shared_ai_service.py` добавлен тест `test_connection_reset_deadlock_regression`: искусственный сбой сокета `ConnectionResetError` перехватывается, рабочий поток гарантированно завершается в пределах `join(0.5)` без зависания, а последующий вызов успешно восстанавливает связь и возвращает вектор.
  - Добавлен тест `test_closed_client_subsequent_request`: явный вызов `client.close()` не ломает клиент, последующий запрос прозрачно переподключается к сервису.

### 2.2. Жизненный цикл общего сервиса и IPC (OS File Lock, Logs, Lifecycle)
* **Проблема:**
  1. `subprocess.Popen` запускался с `stdout=PIPE, stderr=PIPE` без вычитывания потоков. При заполнении 4–64 КБ буфера ОС процесс инференса блокировался на `sys.stdout.write()`.
  2. Файловый замок запуска использовал `open(..., 'x')`. При аварии процесса оставался файл, блокирующий повторный запуск; блок `finally` удалял файл даже если вызывающий клиент не владел замком.
  3. Не передавался `--state-dir`: дочерний процесс регистрировал `ai_service.json` в стандартной директории, а не в переданной тестовой или изолированной.
  4. При таймауте запуска дочерний процесс оставался висеть в памяти в качестве зомби.
* **Решение:**
  - **Отвод логов:** Потоки `stdout` и `stderr` дочернего процесса перенаправлены в файл `inference_service.log` в `state_dir` (`log_file = open(log_path, "a", encoding="utf-8")`, `stdout=log_file, stderr=subprocess.STDOUT`). Буферы ОС не переполняются, а все логи доступны для отладки.
  - **Настоящий OS File Lock (`ProcessFileLock`):**
    - На Windows используется низкоуровневая блокировка диапазона байтов ядра ОС: `msvcrt.locking(f.fileno(), msvcrt.LK_NBLCK, 1)`. На Unix используется `fcntl.flock`.
    - Ядро Windows автоматически снимает блокировку при завершении или аварийном падении процесса (Crash Recovery), исключая зависшие замки.
    - В файл записываются PID и метка времени. Метод `release()` освобождает и удаляет файл **только если замок был фактически захвачен данным клиентом** (`if self.acquired`).
  - **Передача `state_dir`:** Дочернему процессу передаётся аргумент `--state-dir <path>`. В [`ai/inference_service.py`](file:///c:/Users/RMatv/OneDrive/Рабочий%20стол/Dev/Refer/ai/inference_service.py) добавлен парсинг CLI-аргументов `--server`, `--state-dir`, `--host`, `--port`, `--fake-engine`.
  - **Контроль таймаута:** При превышении таймаута инициализации (60 с) вызывается `proc.kill()` и `proc.wait(5.0)`, что предотвращает появление осиротевших процессов.
* **Тесты:**
  - `test_process_file_lock_mutual_exclusion_and_release`: проверка эксклюзивного владения замком и освобождения.
  - `test_process_level_shared_service_with_fake_engine`: запуск реального независимого процесса ОС через `Popen` с легковесным `--fake-engine`, проверка разделения единого PID двумя клиентами, закрытие одного клиента без влияния на второй, корректный `shutdown` и `proc.wait()`.
  - **Честная фиксация по реальной модели:** Автоматизированные тесты выполняются с легковесным `FakeEngine` и TCP IPC, чтобы не загружать 2 ГБ весов PyTorch/CUDA в оперативную память при каждом тестовом запуске. Совместная работа реального SigLIP 2 проверяется при штатном запуске приложения.

### 2.3. Наблюдатель внешних изменений мудбордов в GUI (`PRAGMA data_version`)
* **Реализация:** В [`ui/widgets/collections_panel.py`](file:///c:/Users/RMatv/OneDrive/Рабочий%20стол/Dev/Refer/ui/widgets/collections_panel.py) постоянный открытый коннект `self._observer_conn` опрашивает `PRAGMA data_version`. При внешних модификациях (MCP tool `refer_board`) испускается сигнал `contentsChanged`, вызывающий `self.reload()`. Если удалён текущий мудборд, испускается `collectionCleared`. В [`ui/main_window.py`](file:///c:/Users/RMatv/OneDrive/Рабочий%20стол/Dev/Refer/ui/main_window.py) слот `_on_collection_contents_changed` обновляет заголовок и крошки, а при очистке сбрасывает отображение.
* **Верификация:**
  - Проверено как внутри одного процесса между отдельными соединениями SQLite, так и **через отдельный процесс операционной системы**: тест `test_external_process_insert_detected_and_reloaded` запускает дочерний процесс Python через `subprocess.run`, выполняющий `INSERT INTO collections`, и верифицирует обнаружение изменения наблюдателем по `PRAGMA data_version`.

### 2.4. Единая политика видимости и доступа к ассетам
* **Проблема:** Ранее `refer_preview`, `refer_project` и `inspect_asset_crop` проверяли только `VisibilityStore.is_hidden()`, но игнорировали `SourceGroupStore.get_disabled_sources()`. Административно отключённые папки и сайты оставались доступными по ID.
* **Решение:**
  - Создан модуль [`mcp_server/access_policy.py`](file:///c:/Users/RMatv/OneDrive/Рабочий%20стол/Dev/Refer/mcp_server/access_policy.py):
    - Функция `is_source_or_path_disabled(source_or_path, disabled_sources)` проверяет точные совпадения доменов, нормализованных путей, а также **рекурсивную иерархию папок** (отключение родительского каталога `C:/Refs` автоматически отключает `C:/Refs/Villa/1.jpg`).
    - Функция `check_asset_access(asset_data, visibility_store, group_store)` возвращает кортеж `(is_accessible, reason)`. Причины строго разделены: `"hidden"` (скрыто пользователем) и `"source_disabled"` (отключен источник/папка).
  - Интеграция по всем инструментам:
    - **`refer_search`:** При передаче `image_asset_id` проверяется доступность референсного кадра с явной ошибкой при нарушении (`"hidden by library visibility policy"` или `"belongs to a disabled source or directory"`).
    - **`refer_preview`:** Исключает как скрытые ассеты, так и ассеты из отключённых источников/каталогов.
    - **`refer_inspect`:** Блокирует доступ с явным информативным сообщением об ошибке.
    - **`refer_project`:** Исключает недоступные ассеты из списка кадров объекта.
    - **`refer_board` (`get`):** Возвращает поля `"is_accessible"` и `"inaccessible_reason"` для каждого сохранённого элемента.
    - **`refer_board` (`validate`):** Включает скрытые и отключённые элементы в список нарушений (`violations`).
    - **`refer_export`:** Пропускает недоступные ассеты при формировании клиентского пакета и возвращает `"skipped_inaccessible_count"`.
* **Тесты:** В `tests/test_access_policy.py` (6 тестов) проверены отключение домена сайта, родительского каталога, вложенной папки, скрытие ассета по ID, валидация в `inspect_asset_crop` и `image_asset_id`.

## 3. Устранение замечаний P2 и оптимизация MCP

### 3.1. Кроп и фотометрия (`refer_inspect`)
* Вырезание кропа по `bbox_norm` с валидацией координат (`0.0 <= x0 < x1 <= 1.0`, проверка на `NaN/Inf`).
* Фотометрия (CIE LAB палитра, `warmth_palette`, глобальный контраст) рассчитывается **строго на вырезанном фрагменте**, а не на исходном файле.
* Поле `"measurement_region"` принимает значение `"crop"` при наличии bbox и `"full"` при инспекции всего кадра.
* Защита от OOM: фрагменты >2560px масштабируются с флагом `"is_downsampled": True`.

### 3.2. Архитектура слотов в мудбордах (`refer_board`)
* В `collection_assets` поддержана колонка `slot_name`.
* Методы `refer_board(action='create')` и `action='add'` принимают `slot_name` (`overview`, `interior`, `facade`, `detail`, `landscape`).
* `action='get'` возвращает назначенные слоты; `action='validate'` возвращает `slot_distribution` и проверяет квоту кадров на один проект (`max_per_project`).

### 3.3. Расширение `refer_taxonomy` и `refer_search`
* В `refer_taxonomy` добавлены срезы `sources` и `groups` со счётчиками и статусом активности.
* В `refer_search` добавлены параметры `sources`, `exclude_tags`, `exclude_project_ids`, `top_only`, `favorites`.
* Поддержка `slot_hint="landscape"` дополняет промпт семантическими терминами окружения.
* Ленивая инициализация `get_ai_client()` в `search_engine`: клиент AI подключается только когда вектор действительно необходим, предотвращая лишние запросы.

## 4. Изоляция тестов и устранение утечек глобального состояния

* **Проблема:** При запуске `unittest discover` в консоли появлялись строки `Loaded FAISS index with 72402 vectors`. Тесты обращались к реальной базе пользователя и индексу FAISS.
* **Устранение утечек:**
  1. В `mcp_server/search_engine.py`: глобальные `get_db_manager()` и `get_faiss_manager()` вызываются только при `search_repo is None`. Если передан изолированный тестовый `search_repo`, глобальные синглтоны базы и индекса не создаются и не загружаются.
  2. В `tests/test_search.py`: в фикстуру `WindowTests.setUp` добавлен патч `patch("ui.main_window.FaissManager")`, возвращающий тестовый индекс с `dimension=3` из временного каталога. Это устранило 15 утечек загрузки боевого индекса при тестировании GUI-сценариев.
  3. Все новые тесты (`test_access_policy.py`, `test_shared_ai_service.py`, `test_mcp_search.py`) используют независимые временные каталоги `tempfile.mkdtemp`.
* **Результат:** Прогон всех 146 тестов проекта не содержит ни одного обращения к боевому индексу с 72 402 векторами.
