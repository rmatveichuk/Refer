## 4. Длинные запросы, лимит токенов и правила для UI / MCP

### 4.1. Архитектурные ограничения энкодера SigLIP 2
1. **[Факт] Физический лимит:** `text_config.max_position_embeddings = 64`. В эмбеддинге позиций `Embedding(64, 1152)` ровно 64 слота.
2. **[Факт] Ошибка текущего кода [ai/engine.py](file:///c:/Users/RMatv/OneDrive/%D0%A0%D0%B0%D0%B1%D0%BE%D1%87%D0%B8%D0%B9%20%D1%81%D1%82%D0%BE%D0%BB/Dev/Refer/ai/engine.py#L111):**  
   В строке 111 вызывается:
   ```python
   self.processor(text=[english_text], return_tensors="pt", padding="max_length", max_length=64)
   ```
   Параметр `truncation=True` **ОТСУТСТВУЕТ**. Так как у токенизатора `model_max_length` равен $10^{30}$, токенизатор возвращает все токены (например, 152 токена для длинного описания).
   При передаче тензора длины 152 в `model.get_text_features` PyTorch выбрасывает:
   ```text
   ValueError: Sequence length must be less than max_position_embeddings (got sequence length: 152 and max_position_embeddings: 64)
   ```
   Метод `ai/engine.py` ловит это исключение в блоке `except` и молча возвращает нулевой вектор `np.zeros(1152)`.  
   Вектор из нулей при расчете L2-дистанции до единичных векторов дает дистанцию $1.0$, которая отсекается порогом, и **пользователь видит пустой экран**.

### 4.2. Анализ положения ключевых слов (Key-at-Start vs Key-at-End)
При безопасном усечении (`truncation=True, max_length=64`):
* Токенизатор сохраняет первые 63 токена и добавляет токен `<eos>` (ID 1).
* **[Факт] Если ключевой объект находится в конце длинного брифа:**  
  В сценарии с описанием проекта на 103 токена:
  * Исходный текст: *«Просторный современный загородный проект с плоской зеленой кровлей, открытыми террасами из термодерева... Главной особенностью является брутальный монолитный бетонный дом среди густых вековых сосен.»*
  * То, что физически попало в модель (63 токена): *«Просторный современный загородный проект с плоской зеленой кровлей, открытыми террасами из термодерева, панорамным остеклением от пола до потолка и высокими потолками. Внутри предусмотрены открытая кухня-гостиная, мастер-спальня и две госте...»*
  * **Суть запроса («бетонный дом среди сосен») была полностью отрезана**. Модель искала «террасы из термодерева и кухни-гостиные».

### 4.3. Отрицания и конкурирующие требования
* **[Факт] SigLIP 2 не понимает языковые отрицания:**
  * Запрос: *«современный дом среди сосен, абсолютно без деревянных элементов, чистый бетон и стекло»*.
  * В выдаче: проект *CAMPout* (ID 119846), где стены обшиты кедром.
  * Упоминание слова «дерево» активирует веса дерева в пространстве CLIP/SigLIP независимо от частицы «без» или «no».

### 4.4. Конкретные правила для UI и MCP

#### Правило для UI (Пользовательский интерфейс):
1. **Препроцессинг:** Обязательно вызывать токенизатор с `truncation=True, max_length=64`.
2. **Ограничение ввода:** В текстовом поле ввода установить предупреждение при превышении 200 символов (~45-50 токенов): *«Длинные запросы обрезаются моделью до 64 токенов. Опишите главное в начале»*.
3. **Отрицания:** Исключать не текстом («без дерева»), а через UI-фильтр тегов: *«Исключить тег: wood»*.

#### Правило для MCP (AI-агент в IDE):
1. Агент **никогда не должен отправлять сырой длинный бриф пользователя** в качестве текстового запроса для векторного поиска.
2. Агент должен выполнять **декомпозицию (Query Extraction)**:
   * `visual_query` (строго 5–15 токенов на английском или русском): лаконичное визуальное ядро кадра (например, `бетонный фасад сосновый лес панорамные окна` или `concrete house pine forest`).
   * `metadata_filters` (отдельные структурированные параметры):
     * `category`: `exterior` / `interior` / `furniture` / `plants`
     * `materials`: `["concrete"]`
     * `exclude_materials`: `["wood"]`
     * `scope`: `top` / `web` / `models`
     * `architect`: `Faulkner Architects`

## 5. Анализ текущей формулы порога (Threshold Audit)

В [ui/main_window.py](file:///c:/Users/RMatv/OneDrive/%D0%A0%D0%B0%D0%B1%D0%BE%D1%87%D0%B8%D0%B9%20%D1%81%D1%82%D0%BE%D0%BB/Dev/Refer/ui/main_window.py#L1371) используется формула:
$$\text{max\_distance} = 2.0 \times \exp(-5.3 \times \text{threshold})$$

### Математический факт:
Так как векторы в FAISS нормализованы ($\|u\| = 1, \|v\| = 1$), квадрат евклидова расстояния связан с косинусным сходством:
$$\|u - v\|^2 = 2 - 2 \cos(u, v) \implies \cos(u, v) = 1 - \frac{\|u - v\|^2}{2}$$

|:---:|:---:|:---:|:---:|:---:|
| **0.10** | 1.17721 | $\ge 0.4114$ | **0.0** | **0.0** |
| **0.20** | 0.69291 | $\ge 0.6535$ | **0.0** | **0.0** |
| **0.30** | 0.40785 | $\ge 0.7961$ | **0.0** | **0.0** |
| **0.40** | 0.24006 | $\ge 0.8800$ | **0.0** | **0.0** |
| **0.50** | 0.14130 | $\ge 0.9294$ | **0.0** | **0.0** |
| **0.60 (по умолчанию)** | **0.08317** | **$\ge 0.9584$** | **0.0** | **0.0** |
| **0.70** | 0.04896 | $\ge 0.9755$ | **0.0** | **0.0** |
| **0.80** | 0.02882 | $\ge 0.9856$ | **0.0** | **0.0** |

### [Факт] Почему текстовый поиск в приложении не работал:
* В кросс-модальном поиске «текст $\to$ картинка» косинусное сходство лучших изображений составляет **$0.15 - 0.35$** (L2-дистанция $1.30 - 1.70$).
* Сходство $\ge 0.958$ бывает **только при поиске дубликатов картинок** (картинка $\to$ та же картинка).
* Текущий порог при 60% требует сходство от **0.958**, что отсекает **100.0% всех релевантных изображений по тексту**.
* **Рекомендация для нового поискового ядра:**
  Отказаться от жесткого экспоненциального порога дистанции для текстового поиска. Использовать чистое ранжирование Top-K (выдавать первые 50–100 лучших кандидатов) либо шкалу относительного сходства.

## 7. Ограничения проверки и критические обнаруженные дефекты

### 7.1. Критический конфликт NumPy 2.x и FAISS в окружении
* **[Факт]** В глобальном Python 3.12 установлен `numpy 2.5.2`, в то время как установленный пакет `faiss-cpu 1.8.0` скомпилирован под старый ABI NumPy 1.x (`0x1000009`).
* При прямом вызове `import faiss` возникает ошибка:
  ```text
  ImportError: A module that was compiled using NumPy 1.x cannot be run in NumPy 2.5.2 as it may crash.
  ```
* В [requirements.txt](file:///c:/Users/RMatv/OneDrive/%D0%A0%D0%B0%D0%B1%D0%BE%D1%87%D0%B8%D0%B9%20%D1%81%D1%82%D0%BE%D0%BB/Dev/Refer/requirements.txt) зафиксирован `numpy==1.26.4`.
* Чтобы строго соблюсти запрет ТЗ на установку/изменение пакетов (`«Не устанавливай пакеты»`), проверочный скрипт использовал встроенный бинарный парсер `collection.index` с прямым memory-mapping и расчетом L2 через PyTorch GPU (что дало 100% математическую эквивалентность FAISS IndexFlatL2 без модификации окружения).
* **Для рабочего запуска приложения пользователю необходимо вернуть `numpy==1.26.4`**, иначе `ui/main_window.py` упадет на импорте `database.faiss_manager`.

## 8. Команда для воспроизведения

Все измерения полностью автономны, не требуют интернета (`HF_HUB_OFFLINE=1`) и перезапускаются одной командой:

```bash
python research/search_audit/run_audit.py
```

Результаты сохраняются в структурированном виде в `research/search_audit/results.json`.
