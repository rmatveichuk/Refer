## Требуемый результат

### 1. Левая панель и настройки

- Вернуть кнопку настроек «гамбургер» в верхний левый угол. Убрать нижнюю кнопку «Настройки». Верхняя строка компактная, без прежней большой служебной полосы.
- Сохранить понравившийся блок поиска: картинка, текст, запуск, очистка запроса. Сохранить поиск по картинке и прямой русский ввод.
- Оставить два понятных режима текста: «По смыслу» и «По названию / бюро». Второй использует записанные названия проектов, авторов, имена файлов и описания, работает без AI. Добавить короткую подсказку: работа студии находится, если сведения о студии есть в базе. Не заменять это автоматическим угадыванием режима.
- Убрать обязательный выбор «Референсы / 3D-модели / Не распределено / Все разделы». Убрать общий список «Все коллекции». Устранить скрытое ограничение по section во всех обычных ветках выдачи, иначе картинки продолжат исчезать после удаления переключателя. Старые ручные назначения разделов не должны ограничивать новую выдачу.
- После поиска — компактный блок уточнений: избранное, «Только ТОП», отдельная кнопка тегов, выбранные метки, дополнительные условия (любой/все, исключающие теги), «Сброс». Растения — коллекции моделей, отдельного обязательного раздела для них не делать.
- Затем заголовок «Источники» с кнопкой «Каталоги…» и оперативное дерево. Фильтры слева не сокращают высоту галереи. Счётчик результатов, размер миниатюр, Галерея/Таблица и статус внизу сохранить.
- «Очистить запрос» сохраняет фильтры; «Сброс» очищает уточнения и оперативный выбор источников до всех включённых, сохраняя запрос и административные отключения каталогов.

### 2. Сделать галочки спокойнее

Белые заполненные квадраты источников сейчас слишком яркие: QTreeWidget::indicator:checked имеет фон и рамку #ffffff в search_panel.py. Сделать их немного темнее, например #929292–#a0a0a0; окончательный оттенок выбрать по реальному окну. Не уменьшать читаемость выбранного состояния. Различать unchecked, checked, partially checked, disabled и hover. Промежуточное состояние показывать явно, например горизонтальной чертой. Согласовать стиль галочек в источниках, каталогах и уточнениях. Использовать существующий механизм иконок либо небольшие локальные SVG при необходимости, не подключать внешние ресурсы ради галочки.

### 3. Дерево групп вместо жёстких разделов

Создать пользовательские группы источников с произвольными названиями и вложенностью. Пример, не обязательная классификация:

```text
Архитектура
  ArchDaily
  Behance
  Локальные референсы
3D-библиотеки
  Растения
    Globe Plants
    Maxtree
  Мебель и декор
Рабочие проекты
  Triple D
    2026
```

- Группа — виртуальная организация; папка — подключённый физический источник; сайт — отдельный источник. Вложенные папки отражают существующую иерархию диска. Пользователь может создать/переименовать группу и перенести группу или подключённый источник в другую группу через понятное действие «Переместить в группу…»; drag-and-drop допустим дополнительно. Исключить циклы. Перенос не перемещает файлы на диске.
- Не навязывать ненадёжное определение содержимого по имени папки. Первоначальное дерево должно сохранить все существующие подключения и административные отключения; допустима нейтральная группа «Без группы». Не требуется сразу идеально классифицировать всё за пользователя.
- Сохранять группы, порядок и привязки стабильными идентификаторами; название группы не является идентификатором. Предпочтительно отдельное версионированное состояние в AppData Refer с атомарной записью, а не миграция рабочей SQLite. Ошибка сохранения не должна сообщать успех или молча потерять прежнее состояние.
- Не дублировать источник в нескольких группах в первой реализации. Перекрывающиеся физические подключения не должны удваивать результаты и счётчики изображений.
- Удаление пустой виртуальной группы допустимо; для непустой предложить перенос содержимого в другую группу. Физическое удаление файлов и удаление записей SQLite в задачу не входит.

### 4. Окно «Каталоги» — центр управления

Заменить плоскую таблицу просторным окном с деревом слева и свойствами выбранного узла справа. Окно должно удобно изменять размер.

- Поиск по имени/пути с сохранением родителей совпадающих узлов; раскрытие/сворачивание веток, полный путь в свойствах/подсказке.
- Свойства: название, путь или сайт, число изображений, доступность, включение в библиотеку. Не блокировать GUI проверками недоступных дисков или сетевых путей; существующую длительную диагностику использовать асинхронно.
- Включение группы распространяется на потомков; промежуточное состояние показывает смешанный выбор. Отключение исключает источник из обычного поиска и дерева слева, сохраняя его изображения/теги/избранное/векторы. Для сайтов то же понятное управление, не оставлять их вне окна каталогов.
- Сворачивание ветки меняет только отображение. Разделять включение библиотеки в этом окне и оперативные галочки в источниках слева.
- Настройки дерева применяются через «Применить», «Отмена» не сохраняет черновик. Действия сканирования/импорта должны иметь явный запуск и согласованную работу с несохранёнными изменениями. По возможности оставлять окно открытым во время операций; прогресс и остановка доступны.
- Верхние действия: «Создать группу», «Добавить папку», «Добавить с сайта». Для выбранной папки: «Пересканировать», «Открыть папку», параметры сканирования.
- В этом же окне разместить доступ к скрытым изображениям/восстановлению и обслуживанию: проверка файлов, индексация. Не возвращать эти кнопки в постоянную верхнюю полосу главного окна.

### 5. Источники слева — оперативная фильтрация

- Показывать дерево включённых пользовательских групп и доступных для выбора источников. Недоступный диск не равен удалённому источнику: показывать его состояние, сохранять записи.
- Галочка группы выбирает потомков, промежуточная галочка — частичный выбор. У виртуальной группы нет собственных изображений; у физической папки могут быть собственные файлы вместе с подпапками.
- Выбор частично включённой папки сохраняет её собственные изображения и исключает снятые ветки. Пустой виртуальный родитель исчезает, если все потомки административно отключены; физический родитель с собственными изображениями остаётся.
- Сохранять оперативный выбор и раскрытие при обновлении дерева; новый выбор должен обновлять активный поиск с существующим debounce и защитой от устаревшего результата. Пустой выбор означает пустую выдачу.
- Оперативный сброс не включает административно отключённые источники. При изменении групп привязка выбора остаётся к источникам, а не к их прежним названиям/позициям.

### 6. Добавление и сканирование

- Парсинг сохранён сейчас в TopToolbar.show_import_dialog, доступен через «Каталоги → Добавить с сайта…». Перенести понятное управление в окно каталогов, сохранить Behance/ArchDaily, ссылку, запуск/остановку и состояние при закрытии/повторном открытии. Закрытие окна не должно случайно обрывать операцию или делать остановку недоступной.
- Добавление папки и повторное сканирование остаются с явными опциями: вложенные папки, пропуск текстур/технических карт, обработка ранее скрытых/удалённых изображений.
- Сейчас пропуск текстур зависит от section=models в FolderImportDialog. После удаления разделов сделать его самостоятельной опцией, сохранить прежнюю выбранную настройку при пересканировании, не потерять фильтр превью 3D.
- Повторное и перекрывающееся сканирование не создаёт повторные записи и не возвращает скрытые изображения. Сохранить существующие проверки нормализованных путей и короткие транзакции.

## Сохранить работающие решения

- Windows AI работает через отдельный локальный процесс ai/process_client.py и ai/inference_service.py. Не возвращать инференс Torch в Qt worker: ранее были зависания и конфликт OpenMP с FAISS.
- SQLite/FAISS-фильтрация выполняется вне GUI через ResultsWorker. Один активный и один заменяемый ожидающий запрос; старый результат не заменяет новый.
- Выдача 400 + 400, ограниченный кеш миниатюр 64 МиБ, четыре активные загрузки, защита видимых миниатюр. Не возвращать неограниченную выдачу/кеш.
- Один клик открывает просмотр, Ctrl/Shift выделяет несколько. Галерея и таблица используют один результат.
- Скрытие обратимое через VisibilityStore; диагностика не удаляет отсутствующие файлы. Метаданные/теги/избранное и векторы сохраняются.

## Проверки

Использовать проектный интерпретатор `.venv/Scripts/python.exe`, не глобальный Python. Запуск: `python -m unittest discover -s tests` из проектного окружения. Старые тесты разделов адаптировать к новой архитектуре с сохранением проверок фильтрации; не удалять проверки ради зелёного результата.

Добавить содержательные сценарии на временных данных:

1. Сохранение/загрузка/переименование/перемещение групп, предотвращение циклов, отмена и ошибка записи.
2. Все прежние источники и отключения сохранены; рабочие изображения не отсекаются скрытым section-фильтром.
3. Включение/отключение родителя, смешанные потомки, собственные файлы физической папки, пустые родители, сайты, пересечение подключений.
4. Выбор источников, теги/исключения/ТОП/избранное, очистка запроса и сброс, сохранение выбора при изменении дерева, отсутствие устаревшей выдачи.
5. Метаданные студии находятся без AI; семантический поиск не потерян. Пагинация и лимит памяти сохранены.
6. Импорт/пересканирование/остановка доступны из каталогов, пропуск текстур работает независимо от старого раздела, закрытие и повторное открытие сохраняют управление операцией.

После тестов проверить реальное Qt-окно при минимальном размере 1200×850 и большом размере: отсутствие обрезанных элементов, доступность прокрутки, читаемость умеренных галочек/частичного состояния, неизменная высота галереи при раскрытии условий. Сохранить снимки в docs/research. `research/search_audit/smoke_layout.py` можно адаптировать; живую SQLite открывать исключительно mode=ro и не запускать DatabaseManager на ней ради скриншота. Асинхронные операции для визуальной проверки подменять тестовыми либо явно не запускать.
