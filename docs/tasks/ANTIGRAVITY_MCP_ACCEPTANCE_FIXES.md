# Gemini: довести MCP до проверенной готовности

Codex проверил передачу 4 октября 2026. Сервер импортируется, через SDK list_tools регистрируются семь функций refer_taxonomy, refer_search, refer_preview, refer_inspect, refer_project, refer_board, refer_export. Проектные тесты: 122 успешно. Это подтверждает регистрацию и прежние функции приложения, но не сквозную работоспособность семи MCP-инструментов. Отдельных MCP-тестов в tests пока нет. Заявление «план выполнен на 100%» преждевременно.

Работать по актуальному docs/MCP_VISION_IMPLEMENTATION_PLAN.md, сохраняя существующие решения Windows/FAISS/AI. Исправить следующее на временных данных, не изменяя рабочую библиотеку ради проверки.

## P1 — исправить до пользовательского подключения

1. **Текстовый поиск по метаданным не работает.** В mcp_server/search_engine.py effective_query применяется только к AI, но не входит в SQL WHERE. На фикстуре с двумя проектами (SAOTA и Other) вызовы execute_search(query='SAOTA', mode='metadata') и query='NO_SUCH_STUDIO' возвращают одинаковые [2, 1]. Реализовать поиск по метаданным через существующий общий поисковый слой. Настоящий hybrid должен поддерживать приоритет текстовых совпадений, сейчас он фактически semantic. Ошибка/недоступность AI не должна молча превращаться в произвольные последние изображения.

2. **Модель дублируется.** get_ai_client создаёт новый AiProcessClient, который запускает собственный ai.inference_service через Popen. Это не подключение к уже загруженной модели GUI и прямо нарушает п.1.3 плана. Реализовать реально общий сервис инференса/IPC с сериализацией запросов и определённым жизненным циклом. Проверить одновременно открытый GUI и MCP: один владелец модели, очередь, таймауты и восстановление после ошибки. Не отключать защиту OpenMP и не возвращать CUDA в Qt worker.

3. **Наблюдение внешних изменений GUI не работает надёжно.** CollectionsPanel._check_external_changes каждый раз вызывает db.get_connection(), возвращающий новое соединение SQLite. data_version сравнивается между разными соединениями. На временной WAL-базе до и после внешнего INSERT значение на новых соединениях равно 2 и 2. Нужен постоянный observer с корректным закрытием/переподключением; сравнивать значения на одном соединении. Проверить реальную внешнюю запись вторым процессом, появление нового набора и обновление содержимого уже открытого набора, а не только списка панели. Таймер не должен блокировать GUI.

4. **MCP обходит правила видимости библиотеки.** Новый execute_search не использует VisibilityStore/SourceGroupStore и не поддерживает источники из спецификации. Агент может получить скрытые картинки и административно отключённые каталоги. Подключить общий фильтрующий слой SearchRepository или расширить его, а не вести расходящиеся SQL-ветки GUI и MCP. Проверки: скрытие, отключение групп/сайтов/вложенных папок, собственные файлы родителя, пустой выбор, теги и исключения, ТОП, мудборд. Прямые вызовы inspect/project/preview должны иметь явно определённую политику доступа к исключённым ассетам.

## P2 — корректность зрения и полнота спецификации

5. **inspect выдаёт палитру исходного кадра вместо кропа.** После создания target_img вызывается extract_photometry(resolved_path), то есть анализируется полный файл. Сделать анализ фактически возвращаемой области и указать область измерений в результате. Проверить двухцветное изображение: левый и правый кроп должны иметь разные палитры. Некорректные bbox (NaN, неверная длина, пустая/обратная область) возвращают явную ошибку, а не молча весь кадр. Ограничить размер декодирования/ответа; сообщать реальные размеры и возможное уменьшение. local_path иногда сам является кешем: is_cache_fallback должен отражать реальное происхождение, а не только выбор поля.

6. **Недостающие части плана.** В taxonomy нет источников/групп; в search нет sources/exclude_project_ids; slot_hint landscape не обрабатывается; в board отсутствуют сохранение slot_name и объяснение выбора по элементам. Фоновый расчёт фотометрии, инвалидирование по изменению файла и калибровка на 200 кадрах не представлены. Реализовать согласованные пункты либо честно пометить отложенными с причинами. Параметры MCP должны иметь ограничения/enum, preview — максимум девять ID, корректные результаты для отсутствующих файлов. Квоты разнообразия должны давать достаточно кандидатов при большом числе кадров одного проекта, а не ограничиваться фиксированным top_k * 4.

## Подтверждение результата

- Добавить изолированные регрессионные тесты для P1/P2. Данные, настройки, индекс, коллекции, экспортные файлы — временные. Настоящую базу использовать только read-only; не создавать DatabaseManager на живой базе ради теста.
- Выполнить сквозной запуск клиент → stdio MCP → initialize/list_tools/call_tool для всех семи инструментов. Проверить настоящие image blocks и JSON, а не только прямые Python-вызовы функций. board/export используют тестовую библиотеку и тестовую папку без сети; отдельно проверяются ошибки и повторные запросы.
- Отдельно проверить совместный runtime GUI + MCP и реальное внешнее обновление открытого мудборда. Тесты с mock AI не доказывают работу общей GPU-модели: это обозначать явно.
- Документировать точную команду запуска, пример настройки MCP-клиента с cwd/проектным .venv, версии зависимостей, порядок применения миграций и ограничения. Не писать «подключён к IDE», пока клиентская конфигурация и вызов не проверены.
- Сохранить отчёт в docs/research/MCP_ACCEPTANCE_REPORT.md с выполненными тестами, выводом протокольной проверки, фактическими ограничениями и оставшимися пунктами. Обновить план по фактическому результату. Не заявлять 100% по одной регистрации инструментов.

Не переиндексировать существующую библиотеку, не собирать EXE, не менять глобальный Python, не чистить старые данные. Codex продуктовый код в этом ревью не менял.
