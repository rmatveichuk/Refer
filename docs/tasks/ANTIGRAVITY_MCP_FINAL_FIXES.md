# MCP: исправления после повторной приёмки 4 октября 2026

Codex повторно запустил весь набор: 136 тестов, 17.307 с, OK. Сквозной MCP-тест проходит. Продуктовый код в этом ревью не изменён. Остались следующие блокирующие замечания.

## 1. P1: зависание клиента при обрыве связи

В ai/shared_service.py SharedAiClient._request удерживает threading.Lock и при исключении вызывает close(), который повторно захватывает тот же нерекурсивный Lock. Вместо RuntimeError возникает deadlock. Аналогично путь без _sock вызывает _connect_or_spawn() под тем же Lock. Воспроизведено без модели: искусственный socket.sendall, выбрасывающий ConnectionResetError; поток _request остаётся жив после join(0.5).

Исправить владение блокировкой и восстановление соединения. Добавить ограниченные по времени регрессии для обрыва, таймаута, закрытого клиента и последующего запроса. Не допускать вечного ожидания Qt worker или MCP tool.

## 2. P1: жизненный цикл общего сервиса

Текущий spawn использует stdout/stderr=PIPE без чтения потоков: при заполнении буфера сервис может заблокироваться. Реализовать отвод/чтение логов. Файловый замок реализован через open(..., 'x'), а не msvcrt.locking, заявленный в отчёте. После аварии остаётся файл, блокирующий запуск; finally удаляет lock даже если вызывающий клиент его не получил. Обеспечить реальное владение замком, восстановление после аварии и один процесс при одновременном старте клиентов. При таймауте загрузки определить судьбу запущенного процесса. Проверить state_dir: дочерний процесс должен использовать ту же директорию регистрации, что запускающий клиент.

Текущие tests/test_shared_ai_service.py используют MockEngine и заранее запущенный сервер в потоке. Это не проверка запуска двух процессов с настоящей моделью. Добавить процессные тесты с лёгким fake engine и отдельно проверить GUI + MCP с реальным SigLIP 2: один PID модели, реальные запросы, закрытие одного клиента, восстановление. Если последняя проверка не выполнена — указать это честно.

## 3. P1/P2: правила доступа не едины

refer_preview, refer_project и inspect_asset_crop проверяют VisibilityStore, но не SourceGroupStore.get_disabled_sources(). Административно отключённый каталог/сайт остаётся доступен по ID. Сделать общий helper политики видимости, учитывающий источник и вложенные отключения. Использовать его для поиска, image_asset_id, preview, inspect, project; определить поведение board/export для уже сохранённых элементов. Не смешивать скрытие отдельных ассетов с отключением источников. Добавить проверки отключённого сайта, родительского каталога и вложенной папки.

## 4. Корректность отчёта и изоляция тестов

tests/test_mcp_search.py вызывает глобальные get_db_manager()/get_faiss_manager() даже при переданном тестовом search_repo. При общем прогоне виден Loaded FAISS index with 72402 vectors — тесты обращаются к рабочему индексу. Проверить и устранить глобальные зависимости для инъецированных тестовых репозиториев; все новые тесты должны использовать изолированные настройки и данные, включая реестры сервиса, групп и скрытых ассетов. Не заявлять, что все проверки исключительно временные, пока это не подтверждено.

Observer-тест использует второе соединение в том же процессе, а не второй процесс, заявленный в отчёте; не проверяет галерею MainWindow. Исправить описание либо добавить соответствующую проверку.

Обновить docs/research/MCP_ACCEPTANCE_REPORT.md по фактическому результату. Отложенные фотометрия/калибровка остаются отложенными; успешный протокол не доказывает работу реальной модели.

Не менять рабочую библиотеку, не переиндексировать, не собирать EXE. Сохранить остальные изменения проекта.
